# Sift — Claude Code instructions

Friendly disk-space cleaner for **macOS, Windows and Linux** (desktop only — no iOS/Android). Tauri 2 (Rust core) + React 19 + TypeScript + Vite + Tailwind 4.

## Commands

- `npm run dev` — Vite-only on :1430. UI mounts with `api.*` fixtures; no Rust runtime.
- `npm run tauri:dev` — full app. First Rust compile takes minutes.
- `npm run demo` / `npm run tauri:demo` — force the prototype's fixtures (screenshots, design review).
- `npm run typecheck` — `tsc -b --noEmit`.
- `npm run build` — `tsc -b && vite build`.
- `npm run tauri:build` — platform bundles to `src-tauri/target/release/bundle/` (unsigned, no updater payload; `src-tauri/tauri.release.conf.json` opts into updater artifacts and needs `TAURI_SIGNING_PRIVATE_KEY` exported).
- Local signed test build (macOS, no notarizing, nothing uploaded): `APPLE_SIGNING_IDENTITY="Developer ID Application: Tim Murphy (UA2RJP3TSL)" npm run tauri:build -- --bundles app`, then `ditto` the `.app` into `/Applications`. A stable signature keeps the Full Disk Access grant across rebuilds; under `tauri:dev` the grant belongs to the terminal instead.
- `npm run dist:mac` / `dist:win` / `dist:nix` — signed release, drafted on `idevtim/sift`. Setup in `RELEASE.md`; never publish the draft yourself. `dist:mac` also bumps and commits `Casks/sift.rb` in `../homebrew-tap` (unpushed); after the user publishes, remind them to push the tap, or new `brew install`s stay a version behind.
- `npm run icons` — regenerate the icon set from `src-tauri/icons/source.png` (rendered from `src/assets/icons/app-icon-sifted-drive.svg`).

## Design

The design handoffs (tokens, copy, motion specs and a clickable prototype) aren't part of this repo. The shipped UI is the reference: keep new screens consistent with it at the 1200×760 window size, and `npm run demo` shows every screen with the prototype's sample data (`src/lib/demoFixtures.ts`).

- Tokens are CSS variables in `src/index.css` (`:root` light, `[data-theme="dark"]` dark) mapped to Tailwind colors (`bg-panel`, `text-mut`, `bg-mint`, `text-tealtx`, …). Fixed teal is `bg-teal` / `teal-2` / `teal-3`.
- **Teal means "you can reclaim this."** Everything else stays neutral. No red, no health scores.
- Everyday screens use plain words — file paths appear only in Power tools. Per-kind copy lives in `src/lib/findingCopy.ts`.
- Platform naming: Finder/Explorer/Files (`fileManagerName`), ⌘ vs Ctrl, Trash vs Recycle Bin.

## Architecture

- **Routing:** `src/routes.ts` is the single source of truth — sidebar groups (`everyday` / `power`), hash routes, and `activeAs` (e.g. Review highlights Home). `App.tsx` maps route → view; unbuilt routes fall back to `_placeholder`.
- **Typed IPC boundary:** `src/lib/tauri.ts` exposes `api`, which invokes Rust commands in `src-tauri/src/commands.rs`. Outside Tauri (or with `VITE_DEMO_MODE=1`) it returns fixtures from `src/lib/demoFixtures.ts`.
- **Serde contract:** `src-tauri/src/models.rs` uses `#[serde(rename_all = "camelCase")]`; TS mirrors in `src/types/api.ts` — keep them 1:1.
- **Scanners** (`src-tauri/src/scanners/`) are read-only. `findings::scan` sizes per-OS locations in parallel (rayon); `disks::list` uses sysinfo and hides the macOS `/System/Volumes/*` APFS mounts.
- **Restore holding area** (`src-tauri/src/restore.rs`): `free_up` re-resolves each category's paths (`findings::targets`), then `RestoreStore::hold` renames them into `<app data>/hold/<entry id>/` and records a `RestoreEntry` in `restore.json` (written to a temp file then renamed). Cross-volume moves fall back to copy + delete. `restore::is_held` sends the Trash and temporary files (apps rebuild caches, so holding them only keeps the space taken) through `delete_permanently` instead; they're recorded with `restorable: false` so Restore can say where the space went. Restore lists held entries first, then the deleted-for-good records under "Cleared for good"; `hide_cleared` drops only those records (no files involved), and the sidebar badge counts held entries only. "Clear now" (`clear_restore`, one entry or all) deletes held entries early; an entry whose files can't be deleted stays listed so nothing is left on disk untracked. `restore` puts items back, using "name (restored)" if the original path is taken. Entries older than 30 days are purged at launch and on every `list`. `ensure_allowed` only permits paths strictly inside home or the OS temp dir, never Sift's own data. Progress streams as `free-progress` events; `useFreeUp` paces the bar to at least 2.4s.
- **Disk index** (`src-tauri/src/scanners/index.rs`): one parallel walk of home (plus `/Applications` on macOS) builds a pruned size tree (≤120 children per folder ≥1 MB; the rest fold into "Smaller items"), and collects Big files, developer artifacts and duplicate candidates as it goes. Every node carries a `Reason` (`system`, `cache`, `trash`, `installer`, `nodeModules`, `rustTarget`, `derivedData`) that drives treemap colour, Explore copy and whether removal is held or deleted (`Reason::deletes_outright`). It powers Explore, Big files, Developer, Duplicates, ⌘K file search, the drive breakdown and the first-scan overlay. `IndexState` builds once (concurrent requests wait and reuse it); `free_up`/`free_paths` call `Index::forget_removed` so views update without a rescan. Speed check: `SIFT_BENCH_DIR=~/Sites cargo test --release bench_walk -- --ignored --nocapture`.
- **Never walked / never offered:** cloud-sync folders (`~/Library/CloudStorage`, `Mobile Documents`, since listing them can trigger downloads), other apps' sandboxes (`Containers`, `Group Containers`, where macOS prompts per app), and Sift's own data. Package contents (`.photoslibrary`, `.app`, `.fcpbundle`, `.git`, …; see `PACKAGE_EXTS`) are never Big-file or duplicate candidates, because removing one file would break the whole thing. Duplicates only look in Desktop, Documents, Downloads, Pictures, Movies, Music and Videos. Cloud files that aren't downloaded (`scanners::is_dataless`, macOS `SF_DATALESS` — iCloud Desktop & Documents, "Optimize Mac Storage") count as 0 bytes (`local_len`), are never Big files/duplicates/old videos, and are never opened (`duplicates::open_local`): reading one makes macOS download it and blocks until it arrives. Long work (hashing) copies what it needs out of the index first and never holds the index lock while reading files. The index walk, duplicate hashing and drive breakdowns run on their own rayon pool (`scanners::background`) so Home's quick checks and anything clicked never queue behind them on the global pool.
- **Duplicates page** (`views/duplicates/`: logic in `dupes.ts`, tiles in `Preview.tsx`): sets carry their BLAKE3 content `hash` (the id) and `kind`; hard links to one file are dropped (`file_id`). Search, type chips, sort and 6-per-page paging are client-side; the keep rule (Oldest / Best place / Newest, picks by hand stored per hash) and "Keep all copies" are local state. `duplicate_preview(hash)` / `duplicate_facts(hash)` (`scanners/previews.rs`) look the copy up in the cached groups (never a UI path) and run only for what's on screen: macOS Quick Look thumbnails cached as `<app data>/previews/<hash>.png` and Spotlight facts via `mdls`; Windows/Linux send small web-decodable photos as-is and no facts, so the drawn tile shows instead.
- **`free_paths(paths, label)`** is the one removal path for Big files, Explore picks, Duplicates, Developer and Apps: one Restore entry per call, labelled. `RestoreEntry.kind` is set for Home categories, `label` for everything else.
- **Apps** (`scanners/apps.rs`): macOS bundles (+ `~/Library` leftovers by bundle id and name; Apple apps skipped), Windows programs from the registry uninstall keys via PowerShell (+ AppData leftovers; runtimes/drivers/updates skipped), Linux Flatpaks, Snaps and AppImages (distro packages aren't listed). `uninstall_app(id)` re-lists and looks the app up by id (never trusts paths from the UI), refuses running apps, runs the app's own uninstaller for `installer`/`flatpak`/`snap` (Windows waits up to 10 min for the registry entry to vanish), then sends the rest through `free_paths`. Bundle ids and names only become path segments via `safe_segment`. `ensure_allowed` permits exactly one thing outside home: a `.app` directly inside `/Applications`. `AppInfo.icon` is just where the icon file is (bundle `.icns`, Windows `DisplayIcon`, Flatpak/Snap/AppImage png/svg); `app_icon(path)` turns one into a data URL on demand (`scanners/icons.rs`: `sips` / PowerShell `ExtractAssociatedIcon`, cached as PNG in `<app data>/icons`), and the row shows the initial until it arrives. Sift never lists itself (`is_sift`). After an uninstall the row folds away (grid-rows collapse) and is dropped from the cached `["apps"]` list rather than re-listing, which re-measures every app; "Just clear caches" patches the cached app the same way.
- **Home categories:** `scan_findings` covers installers, Trash, temporary files and App leftovers (`scanners/leftovers.rs`, macOS: reverse-DNS folders in `~/Library` whose vendor has no installed app/agent, untouched 90 days, unknown to Spotlight). `index_findings` adds Duplicate photos (every copy but the oldest of each photo group, re-checked by size at free time) and Large old videos (≥100 MB, not opened in a year) from the index; `useFindings` merges both queries. Order at launch: the quick checks run first; `useScan` (and `index_findings`) only start once they're back, so Home fills in within seconds, then shows live walk progress (`Looking` in HomeView) until duplicates and old videos arrive. `leftovers` asks Spotlight about all candidate ids in one `mdfind`. The Windows Recycle Bin is sized and emptied through the shell (`scanners/recycle_bin.rs`, `SHQueryRecycleBinW`/`SHEmptyRecycleBinW`) and recorded with `RestoreStore::record_deleted`.
- **Review → "See all"** (`views/review/FindingView.tsx`, route `finding`, `findingStore`): `finding_items(kind)` lists what a Home category would remove (`findings::items`, or the index's duplicate extras / old videos), biggest first, with plain-words locations and `held` (Restore vs deleted for good, from `Reason::deletes_outright`). Each item can be shown in the file manager or removed alone through `free_paths`, which also takes the Linux `.trashinfo` record along (`findings::with_trash_records`). The query key sits under `["findings"]` so any removal refreshes it. The Windows Recycle Bin can't be listed item by item.
- **External drives** (`scanners/volume.rs`, `drive_breakdown`): a read-only walk sorted by file kind (`scanners/kinds.rs`), with copies of this computer's files (sampled hashes against the index's duplicate candidates) shown as "Can be freed" but never cleaned. Backup drives and the system drive are never walked.
- **Onboarding** (`components/overlays/Onboarding.tsx`): welcome → how it works → Full Disk Access (macOS only; Windows/Linux skip it since Sift has nothing there that needs admin) → preferences → "Start first scan". `prefs.onboarding` (`{step, mode}`) is persisted so "Reopen Sift" (`relaunch`, macOS applies Full Disk Access to a fresh process) resumes at the same step. Until it's done, `App` renders only onboarding and `main.tsx` skips the findings prefetch, so nothing scans (and macOS asks about no folders) before access is granted. `access::granted` probes `TCC.db` / `~/Library/Safari` / `~/Library/Mail` (these never prompt); `useFullAccess` polls it every second on the permission step and on window focus. Without access, Home shows a sand banner that reopens just the permission step (`mode: "permission"`). ⌘K → "Replay onboarding".
- **Weekly check-up** (`src-tauri/src/checkup.rs`): `set_weekly_check(enabled)` (called from `App` at every launch and whenever `prefs.weeklyCheck` changes) registers a Sunday 10:00 job that runs Sift with `--weekly-check`: a launchd agent in `~/Library/LaunchAgents` (macOS), a Task Scheduler task (Windows, `-StartWhenAvailable`), or a systemd user timer (Linux, `Persistent=true`). `lib.rs` handles that flag before the Tauri builder, so there's no window or webview: it sizes Home's safe categories with `findings::scan` and posts one notification through `notify-rust` if they reach 1 GB. It never removes anything, and it skips the check on macOS without Full Disk Access (a background permission prompt would come out of nowhere). `IDENTIFIER` there must match `tauri.conf.json`.
- **Overlays** (onboarding in permission mode, first scan, ⌘K, toasts) render at the shell root, outside the route-keyed `<main>`. The first-scan overlay plays once (`prefs.firstScanDone`); "Replay first scan" rescans with it showing. Query keys: `["scan"]` is the summary (invalidate to rescan); `["index", …]` reads from the built index.
- **State:** TanStack Query for anything backed by `api.*` (`src/lib/queries.ts`). Zustand for UI state: `prefsStore` (persisted: theme, sound, power tools open, weekly check-up, onboarding step/mode, `firstScanDone`), `selectionStore` (Review toggles; unset ids default to `safety === "safe"`), `freeStore` (the in-flight free-up shared by Freeing and Done), `scanStore` (live scan progress + first-scan overlay), `toastStore`, `findingStore` (which category "See all" shows), `pickStore` (Explore → Review picks), `exploreStore`, `paletteStore` and `updateStore`.

## Safety rules (non-negotiable)

- Never delete in place: removals move to a per-volume Sift holding area (same-volume rename) and stay in **Restore** for 30 days.
- Permanent deletes are limited to: emptying the Trash/Recycle Bin, caches and build output that apps and tools rebuild (`Reason::deletes_outright`: caches/temporary files, `node_modules`, Rust `target/`, Xcode DerivedData), and an explicit two-click "Clear now" in Restore. The UI labels each one as permanent ("Delete for good", "Cleared right away"), and Restore records where the space went.
- Backup volumes (`Drive.protected`) are read-only to Sift. Never touch OS-protected paths.

## Gotchas

- Tauri capabilities are explicit — new plugin permissions go in `src-tauri/capabilities/default.json`.
- The frontend must keep working in plain browser mode. When adding `api.*` calls, add a fixture fallback.
- Sounds go through `play()` in `src/lib/sound.ts` (respects the mute pref and backgrounded windows).
- Results of actions (removed, uninstalled, cleaned, ejected, failures) are toasts, not inline banners: `toast(text, { tone, action })` from `stores/toastStore.ts`, rendered by `Toaster` at the shell root (bottom-right, leaves after ~4s, "problem" stays longer, hover pauses). Always remove one with `dismiss(id)`: it animates out (fade, slide, height folds so the rest glide into place) before it's dropped; more than 3 dismisses the oldest the same way. Banners (`Note`) are for standing status, like an uninstaller still running.
- Removing a row (Review → "See all", Apps): spinner on its button while it runs, then the row folds away (grid-rows collapse, ~350ms) before leaving the list.
- Anything loading or working shows a spinner: `Loading` (spinner + muted line) for screens, `Busy` inside a button while its action runs (`components/ui/Spinner.tsx`). Neutral colour, never teal.
- **CPU budget:** both rayon pools (the global one, set in `lib.rs`, and `scanners::background`) use `pool_threads()` = a quarter of the cores, 2–6, and background threads run at macOS "utility" QoS (`lower_priority`). Full-width pools hit 750% CPU. Don't add `par_iter` work outside these pools, and re-measure with `bench_walk` under `/usr/bin/time -l` after touching the walk. Removals refresh through `refreshAfterRemoval` (debounced, one refresh per burst; Apps is only marked stale), and `forget` prunes the cached duplicate groups (`duplicates::without`) instead of re-hashing.
- The background scan pool (`scanners::background`) has 64 MiB thread stacks because the index walk recurses per folder level; the 2 MiB default overflowed (crashed) on deeply nested trees. `deeply_nested_folders_dont_overflow` guards it.
